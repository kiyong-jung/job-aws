# 데모 UI 문구 규칙 (토스 라이팅 8원칙 기준)
출처: https://toss.tech/article/8-writing-principles-of-toss
대상: 공고 입력 → 노란 형광펜 → 역량 표 데모. 말투는 해요체, 한 문장은 짧게.

1. Predictable hint: 누르면 무슨 일이 생기는지 미리 알려 준다.
   - 전: [분석] → 후: [핵심 문장 찾기]
   - 전: 파일을 업로드하세요 → 후: 공고 파일을 끌어다 놓으면 핵심 문장을 표시해요
2. Weed cutting: 빼도 뜻이 같은 단어는 뺀다.
   - 전: 문장을 나누고 있는 중입니다... → 후: 문장을 나누는 중
   - 전: 분석을 시작하시려면 → 후: 공고를 붙여넣으면 바로 시작해요
3. Remove empty sentences: 화면에서 겹치거나 채우기용인 문장은 없앤다.
   - 전: (빈 표) 아직 데이터가 없습니다. 공고를 입력하면 결과가 표시됩니다. → 후: 공고를 넣으면 역량이 여기에 정리돼요
   - 전: 진행 문구 아래 "잠시만 기다려 주세요" 반복 → 후: 단계 문구만 남김
4. Focus on key message: 지금 확인할 것만 말한다.
   - 전: 분석이 완료되었습니다. 총 12개의 문장이 하이라이트되었으며... → 후: 역량 12개를 찾았어요
   - 표 머리글은 역량 / 유형 / 필수·우대 / 근거 문장 네 개만, 설명문 없이
5. Easy to speak: 전문 용어, 문어체를 풀어 쓴다. 소리 내어 읽어 어색하면 고친다.
   - 전: 파싱 실패 / 토큰화 중 → 후: 읽지 못했어요 / 문장을 나누는 중
   - 전: 하이라이트 추출 → 후: 핵심 문장 표시
6. Suggest over force: 시키지 말고 권한다. 겁주지 않는다.
   - 전: 텍스트를 반드시 직접 붙여넣어야 합니다 → 후: 공고 내용을 직접 붙여넣어 볼까요?
   - 전: 입력이 없으면 분석할 수 없습니다 → 후: 내용을 넣으면 시작할 수 있어요
7. Universal words: 나이·업계와 상관없이 알아듣는 말. 지어낸 영어, 약어를 쓰지 않는다.
   - 전: 필수/우대 → 후: 필수·우대는 그대로 두되 유형 칸은 "지식·기술·태도"처럼 쉬운 말
   - 전: URL 크롤링 차단 → 후: 이 주소는 내용을 가져올 수 없어요
8. Find hidden emotion: 사용자가 막혔을 때 마음을 먼저 읽는다.
   - 전: 오류: 로그인이 필요한 페이지입니다 (403) → 후: 로그인해야 볼 수 있는 페이지예요. 공고 내용을 복사해 붙여넣어 주세요
   - 전: 분석 실패 → 후: 이번엔 못 읽었어요. 다시 해 볼까요?

## 요소별 확정 문구 (위 원칙 적용본)
- 입력창 placeholder: 공고 주소를 넣거나 내용을 붙여넣어 보세요
- 드롭존: 공고 파일을 여기에 끌어다 놓아요 (PDF, 이미지, 텍스트)
- 버튼: [핵심 문장 찾기] [다시 해 보기] [내용 붙여넣기] [표 복사]
- 진행 문구(단계별 한 줄): 공고를 읽는 중 → 문장을 나누는 중 → 핵심 문장을 찾는 중 → 역량을 정리하는 중
- 오류(주소 막힘): 이 주소는 읽을 수 없어요. 공고 내용을 복사해 붙여넣어 주시겠어요?
- 오류(파일): 이 파일은 읽지 못했어요. 다른 파일이나 붙여넣기로 해 볼까요?
- 빈 상태(오른쪽 패널): 공고를 넣으면 여기에 보여 드려요
- 빈 상태(표): 공고를 넣으면 역량이 여기에 정리돼요
- 표 머리글: 역량 / 유형 / 필수·우대 / 근거 문장
- 완료: 역량 N개를 찾았어요. 노란 문장을 누르면 표에서 해당 행을 보여 줘요

## 공통 점검
- 느낌표·이모지·"죄송합니다" 반복 금지. 숫자는 아라비아 숫자.
- 한 문구 한 메시지. 두 문장 넘으면 줄인다.
