## 0. 상태와 사건 (모든 단계의 바탕)
- `store.stack` 하나, `panel.reveal(쪽)` 하나만 쪽을 바꾼다 (그대로). 쪽 차례 `ORDER = posting search adapt materials weeks`. `sample` 은 `adapt` 로 이름을 바꾼다 (③ 이 응용 프로젝트 쪽이 된다).
- 새 상태 하나: `store.project = {base, parts:[{from, take, cids}], rows: Map(cid → {level, by})}`. `by` 는 그 역량을 채운 것(`null` = 바탕, 숫자 = 빌린 부분 차례). 덮기 띠, 덮기 표, ③ 쪽, 4단계 표가 모두 이것만 읽는다 (FUE §2 "한 필드를 양쪽이 읽는다").
- 사건은 지금처럼 "서버 사건 하나 = 화면 움직임 한 번". 새로 더하는 사건은 아래 셋뿐이다. 모르는 사건은 `Object.hasOwn` 으로 거르는 것도 그대로.

| 단계 | 사건 | 모양 (pipeline.py 머리말에 그대로 적는다) |
|---|---|---|
| 2 | `adapt` | `{base:{key,title,kind,venue,url}, parts:[{from:{key,title,kind,url}, take, badges}], before:{있음,일부,없음}}` `cover` 29번 뒤, 한 번 |
| 2 | `fill` | `{cid, row, badges, by, level}` 빌린 부분이 채운 역량 하나. 빌린 부분 차례로 |
| 2 | `done` | `{levels:{있음,일부,없음}, before:{…}}` (앞뒤 셈 둘 다. 화면은 셈을 짓지 않는다) |
| 3 | `steps` | 지금 + `project:{title}` (진행 글이 "응용 프로젝트" 를 말하게) |
| 4 | `work` | `packages[]` 에 `from` 더하기: `"base"` 또는 빌린 부분의 `key`. `steps` 에 `project:{title, parts:[{key,title}]}` |

- 2단계 `stage` 는 다섯이 된다: `search → scan → rerank → judge → pick → adapt`. 마지막 진행 글 "빌릴 부분을 찾는 중" ↔ "빌릴 부분 N개를 붙였어요" (S12, 숫자는 `adapt.parts.length`).
- 4단계 끝 사실의 "2단계에서 고른 것과는 다른 샘플에서 만들었어요" 는 저장본이 응용 프로젝트에서 나오면 지운다 (거짓이 된다). 시험의 "손으로 만든 예시" 검사도 같이 바꾼다.

## (a) 2단계 갱신
**깔때기 띠 네 칸** (data_spec 권고 5 + 사용자 11/18):
- `DB에 모인 프로젝트 111,753개 › 낱말로 모은 후보 1,000개 › 역량마다 다시 고른 후보 100개 › 점수 1위 1개`. "뜻으로 다시 고른"보다 사용자 말("Cohere per competency")에 가까운 "역량마다". 견준 100은 칸이 아니라 칸 판 아래 "100개 모두 견줘 봤어요".
- 띠는 `grid-template-columns: auto 16px auto 16px auto 16px auto` (`›` 칸 고정 16px = `--s4`). 지금 간격 들쭉날쭉을 구조로 막는다. 111,753 만 `--fs-display` 32, 나머지 20.
**필수 먼저 순위를 쉬운 말로**:
- 순위 표 머리 아래 한 줄을 바꾼다: "다루면 1점, 일부면 0.5점이에요. 필수를 하나라도 더 다루면 우대가 아무리 많아도 앞서요. 필수가 같으면 우대, 그다음 나머지로 견줘요."
- 칸 판의 짙기는 필수 점수(5점 만점)만. 범례 "칸 하나가 후보 하나예요. 짙을수록 필수를 많이 다뤄요". 고르기의 FLIP 차례는 (필수, 우대, 나머지) 차례다. 필수만으로 줄 세우면 2·3위가 바뀔 수 있으니 서버가 `pick` 에 `order`(100개 순위 번호 차례)를 보내고 화면은 그 차례만 따른다 (화면이 순위를 셈하지 않는다).
- 맨 위 한 줄: **111,753개 중 1개** / "점수 1위 · duoan/mega-data-factory · 필수 5개 다 다뤄요". (필수 5점 중 5점은 "다 다뤄요"가 소리 내 읽기 쉽다. 아니면 지금 꼴 "필수 5점 중 5점" 유지)
**응용 프로젝트로 끝내기** (바탕 + 빌린 부분 → 하나):
- 대화: 덮기 글 뒤에 한 줄 "필수 5개는 이 저장소가 다 다뤄요. 빠진 역량은 다른 프로젝트 3개에서 부분을 빌려 채웠어요." 그 아래 카드 하나 `응용 프로젝트 보기` (지금 샘플 카드 자리, `aria-expanded` 는 ③ 쪽일 때 참). 큰 숫자는 더 넣지 않는다 (답 하나 = 큰 숫자 하나).
- 덮기 띠 29칸: `cover` 때는 지금처럼 있음(먹 채움)·일부(왼쪽 절반)·없음(테두리). `fill` 이 오면 그 칸이 "빌려 채움" 모양으로 바뀐다: 먹 60% 채움 + 칸 안 위쪽 2px 먹 선. 색만이 아니라 모양으로 가른다 (S4). 범례에 "빌려 채움". 칸 바뀜은 움직임 없음 (②·③ 의 주 움직임은 따로).
- 덮기 표에 칸 하나: `채운 곳` = "이 저장소" / "빌림 · NVIDIA-NeMo/Curator". 표는 그대로 접힘.
- ③ 쪽 "응용 프로젝트": 맨 위 쪽 제목(20) "duoan/mega-data-factory 에 3곳을 빌려 붙였어요". 아래 바탕 카드 하나(제목, 저장소·★382, `원문 사이트에서 보기`), 그 아래 32px 줄 목록 "빌린 부분" 3줄: `[문장 배지] 빌린 것(take) · 출처 제목`. 바탕 README 요약과 근거 구절은 줄 목록 아래에 그대로 (접어 둔 `README 앞부분 보기`).
- ③ 의 주 움직임 하나: `fill` 사건의 빌린 부분이 처음 나올 때 그 줄이 아래 12px 에서 올라오며 나타난다 (240ms, transform·opacity). 같은 부분의 두 번째 `fill` 은 줄의 배지만 하나 더한다 (움직임 없음).

## (b) 3단계 교육자료
- 대화 답: 맨 위 **84시간 중 51시간** / "큰 것 17개는 자료로 · 작은 것 11개는 프로젝트를 하면서". 그 아래 짧은 줄 셋 (지금 그대로) + `12주 계획 짜기`.
- **대화의 28줄 표를 지우고 ④ 쪽 목록 하나만 둔다** (S1 D 가 목록 자리를 막대 아래로 정했다. 같은 줄이 두 곳이면 짝·접기 상태가 둘이 된다). 대신 ④ 쪽 목록 줄 앞에 문장 번호 배지(20px)를 단다. 줄을 누르면 지금처럼 ① 공고 쪽으로 가서 그 문장을 켠다 (근거 U14 는 유지).
  → 리드가 대화 표를 남기기로 하면, 반대로 ④ 쪽 목록을 막대 아래 "지금 고른 것" 한 줄로 줄인다. 둘 다 남기는 것만은 피한다.
- ④ 쪽: 머리 "84시간 중 **51시간**"은 막대 위 이름표(13)로 낮추고 20 큰 숫자는 대화 답에만 (S9). 막대 높이 24px, 목표 선 2px, "목표 84시간"(12). 조각 `transform-origin: left` 확인.
- 움직임: `item` 큰 것마다 조각 하나 scaleX 0→1, 240ms (S6). 작은 것은 목록 줄만 붙고 움직임 없음. 끝나면 `data-now` 고리 뗌.
- 진행 접힘 글 (3·4단계 모두, chat.js 한 곳): `✓ 4가지를 했어요 · 펼쳐 보기` (지금 "4단계 끝 · 단계 보기"는 큰 단계 번호와 부딪힌다. "과정" 도 머리줄 단추와 겹쳐 피한다).
- 진행 글: "응용 프로젝트에 필요한 공부할 거리 28개를 큰 것과 작은 것으로 나누는 중" → "…나눴어요".
- 접근성: 막대 `role="img"` 의 `aria-label` 은 사건마다 고치되 live 영역에 넣지 않는다. 알림은 단계마다 한 번, 끝에 "공부 84시간 중 51시간을 골랐어요. 자료가 없는 큰 것 4개" 한 번 (FUE §3 live region, S15).

## (c) 4단계 12주 계획
- 대화 답: **12주** / "한 사람이 한 주에 14시간까지 · 9주는 그 안에, 3주는 넘어요" (지금 그대로). 주별 표는 그림의 글 대안이다 (차트의 데이터 표, FUE §3 "Color is not the only way"). 그래서 3단계와 달리 남긴다. 표의 `프로젝트` 칸에 일 이름 뒤 출처가 빌린 부분이면 12px 흐린 글 "· 빌림".
- 짧은 줄 하나 더: "프로젝트 일 10개 중 7개는 바탕 저장소에서, 3개는 빌린 부분에서 왔어요." (셈은 `work.packages[].from` 에서 화면이 세지 않고 `done` 에 `from:{base, borrowed}` 로 받는다)
- ⑤ 쪽: 그림은 그대로 (S1). 프로젝트 조각에 새 색을 쓰지 않는다. 조각 `title`·주 칸 `aria-label` 에 "원본 영상에서 조각 뽑기 (바탕)" / "(빌림 · Curator)".
- **칸 넘침 버그를 구조로 막기**: `.col` 에 `overflow: clip` 은 넘침 글("+1시간 18분")을 자르니 쓰지 않는다. `.col-stack` 에 `width:100%; contain: layout`, 조각은 `width:100%` 고정, 넘침 글은 `.col-over` 를 `position:absolute; left:50%; translate:-50%` 로 칸 너비 계산에서 뺀다.
- 키보드: 주 칸은 `role="img"` 그대로 (초점 안 받음). 키보드 길은 대화 주별 표 줄 단추 하나 (`aria-pressed`, 위아래 화살표). 그림의 `pointerenter` 와 같은 일을 줄의 `focus` 가 한다 (FUE §3 "hover 는 focus 로도").
- 움직임: `placed` FLIP 560ms (띠 → 주 칸), `work` scaleY 240ms (S6·S7). 390 에서 FLIP 은 띠와 주 칸이 한 화면에 없으면(띠가 스크롤 밖) 건너뛰고 끝 그림만.

## (d) 다섯 쪽의 단계 길과 넘기기
- 단계 길: `1 공고 읽기 › 2 프로젝트 찾기 › 3 응용 프로젝트 › 4 교육자료 › 5 12주 계획`. 600px 아래는 지금 쪽만 이름, 나머지 번호 (그대로). 지금 `aria-current="step"`, 안 그린 쪽 `aria-disabled`.
- 쪽이 밀려 들어오는 때는 둘뿐: (1) 사용자가 답 끝 단추를 눌러 단계를 시작할 때 (②, ④, ⑤), (2) 같은 단계 안의 서버 사건 `adapt` (③). 넘기기는 280ms `--t-view`, transform·opacity (그대로).
- **사용자를 끌고 가지 않기**: (2) 의 자동 넘기기는 사용자가 지금 단계 쪽을 보고 있을 때만 한다. 뒤로·단계 길로 다른 쪽에 가 있으면 넘기지 않고, 단계 길 ③ 에 점(6px 먹)과 `aria-label` "3 응용 프로젝트, 새로 그렸어요" 만 단다. 누르면 점이 사라진다. (`panel.reveal` 에 `{auto:true}` 한 인자: 맨 위가 그 단계의 앞 쪽이 아니면 무시)
- 넘기기가 도는 중 또 `reveal` 이 오면 앞 움직임을 `finish()` 하고 시작한다 (두 쪽이 겹쳐 보이는 때가 없게).
- 초점: 사용자가 누른 단추가 사라지면 새 쪽 제목(`h2 tabindex="-1"`)으로. 자동 넘기기는 초점을 옮기지 않고 `role="status"` 로 "응용 프로젝트 쪽을 열었어요" 한 번.
  (S15 "쪽이 바뀌면 초점은 새 쪽 제목으로"와 README "초점은 사용자가 누른 때만"이 부딪히는 곳이다. 2절 쪽인 README 를 따른다: 자동 넘기기 때 초점을 뺏으면 표를 읽던 키보드 사용자가 길을 잃는다.)
- 1024 아래: 단계가 시작되면 `과정` 보기로 넘어감, 결과는 `대화` 점과 `대화에서 결과 보기` (그대로). ③ 자동 넘기기는 `과정` 보기일 때만.
- 비우기 `reset()` 한 곳에 `store.project` 와 `adapt` 쪽을 더한다. `CLEAR`/`FORGET` 표에 `adapt` 한 줄.

## (e) shots.py 가 더 볼 것 (사진 + DOM 검사)
사진 이름 새로: `12-scene-d-adapt`, `13b-adapt-panel`, `25-weeks-from`, `18-reduced-adapt`, `26-auto-push-away`.
1. **찍기 전에 움직임이 다 끝났는지**: `document.getAnimations().filter(a => a.playState === 'running').length === 0` 을 기다린 뒤 찍는다. 중간 사진은 사건과 사건 사이(앞 움직임이 끝난 때)에 찍는다. 지금 22-weeks-placing-390 같은 흩어진 사진을 막는다.
2. **칸 안에 있는지**: 주 칸 12개 너비가 모두 같고(±1px), 각 `.col-stack` 의 모든 조각 사각형이 그 `.col` 사각형 안 (가로). 깔때기 `›` 칸 셋의 너비가 같다.
3. 2단계: 띠 네 칸 글이 위 문자열 그대로, 칸 판 100개, FLIP 끝 화면 차례 = 저장본 `ranking` 의 (필수, 우대, 나머지) 차례, 1위 고리 = 맨 앞 칸 = duoan/mega-data-factory. 순위 설명 줄 문자열 그대로.
4. 응용: `adapt` 뒤 덮기 띠의 "빌려 채움" 칸 수 = `fill` 사건 수 = 저장본, 칸 모양(위 2px 선)이 있음 칸과 다름, `done.levels` 와 덮기 글 셈이 같음, ③ 쪽 빌린 줄 수 = `parts` 수, 각 줄의 배지 = 저장본 badges.
5. 자동 넘기기: ① 에 돌아가 있는 동안 `adapt` 가 오면 더미 맨 위는 그대로 `posting`, 단계 길 ③ 에 점, `document.activeElement` 는 그대로. ② 를 보고 있으면 `adapt` 쪽이 맨 위, 초점은 그대로, status 글 한 번.
6. 초점: 단추로 시작한 넘기기 뒤 `activeElement` = 새 쪽 `h2`. 뒤로 단추 뒤에는 뒤로 단추에 남음 (지금 검사 유지).
7. 3단계: 대화 답에 28줄 표가 없음(채택하면), ④ 쪽 줄 배지 = 저장본 badges, 진행 접힘 글 "4가지를 했어요 · 펼쳐 보기". 4단계도 "3가지를 했어요 · 펼쳐 보기".

9. 움직임 줄이기 (1440, 390): ③ 빌린 줄·④ 조각·⑤ FLIP 이 `getAnimations()` 0개이고 끝 그림이 저장본과 같음. 넘기기도 바로.
