## shots.py 판정: 한 번에 끝나지 않는 것은 코드가 아니라 돌리는 환경 문제다

- **확인한 것:** 지금 코드로 새 서버(:8791)와 새 Chrome(디버깅 포트 9471)을 써서 shots.py 복사본(포트와 저장 폴더만 바꿈)을 처음부터 끝까지 한 번에 돌렸다.
  - 세 크기 장면 → regressions → reduced → cutoffs 순서로 사진 100장을 찍었다. 01:38:11 에 시작해 01:42:41 에 끝났고(약 4분 30초) exit 0 이다.
  - 페이지 열기 시간 초과와 단언 실패는 없었다. 3초 움직임 대기 경고 한 번(06-mid-replay-table-1024)은 실패가 아니다.
  - 로그는 scratchpad/fe_r1/run1.log 에 있다.
- **그래서 원인은 코드가 아닐 가능성이 크다.** 지금 저장소의 `shots/` 에는 `25-report-result-*` 사진이 하나도 없다. 그리고 01:21~01:26 에 JS·CSS 를 고친 시각과 01:30~01:36 에 찍은 사진이 겹친다. 아래 셋 중 하나로 보인다.
  1. **고치는 중에 돌림.** 서버는 static 을 요청마다 디스크에서 읽는다. 모듈 하나가 고치는 도중 깨진 상태로 읽히면 `#send svg` 가 생기지 않는다. 그러면 `open()` 의 `until(... !!document.querySelector('#send svg'))` 이 20초 뒤 "page-load timeout"으로 끝난다.
  2. **두 번 겹쳐 돌림.** shots.py 의 Chrome 디버깅 포트는 9333 으로 고정이다. 앞 실행이 남아 있으면 새 Chrome 이 포트를 못 잡는다. 그러면 `/json/list` 가 앞 Chrome 의 페이지를 돌려주고, 두 스크립트가 한 페이지를 번갈아 navigate 한다.
  3. **도구 시간 제한.** 한 번 도는 데 4분쯤 걸린다. Bash 기본 제한 2분으로 돌리면 중간에 죽는다. 백그라운드로 돌리거나 제한을 10분으로 둔다.
- **shots.py 에 두면 좋은 것 (코드 쪽 보강):**
  - `open()` 의 시간 초과 메시지에 `document.readyState`, 모듈 오류(`Runtime.exceptionThrown`), 실패한 요청을 함께 찍는다. 그러면 다음에는 원인이 바로 보인다.
  - 디버깅 포트를 0 으로 두고 `DevToolsActivePort` 파일에서 읽는다. 그러면 겹친 실행이 서로를 조종하지 못한다.
  - BASE 를 인자(`--base`)로 받는다. 그러면 고치는 동안 쓰는 서버와 찍는 서버를 나눌 수 있다.

**판정: ship after top 3** (1 ③ 셈과 칸 원천 하나로, 2 리포트 한 곳에만, 3 깔때기 띠 grid). 4·5·6 은 같은 날 함께 고치면 좋다.
