# 공부 시간 고르기 설계서 (리드가 다섯 설계안을 합침, 2026-11-18)

근거: `design/budget_brief.md`, `design/proposals/budget-{frontend-design,taste-skill,ui-ux-pro-max,toss-writing,frontend-ui-engineering}.md`. 갈린 곳은 이 파일이 정한다. `DESIGN_RULES.md` 1절(사용자 규칙, 새 U4-1 포함)이 이 파일보다 위다. 데이터 열쇠는 `design/data_spec.md` 의 새 절(데이터 에이전트가 씀).

## 0. 정한 것 한눈에
- 이름은 어디서나 "하루 N시간" (안·예산 금지). 고르기 칸 이름표는 "하루 1시간 · 84시간" 한 줄.
- 처음 고르기는 대화에서 단추 셋, 바꾸기는 ④⑤⑥ 쪽 머리의 세 칸 고르기 하나. 바꿔도 다시 틀지 않고, 대화에 새 말도 붙지 않는다. 그린 단계의 그림과 대화 답이 그 자리에서 새 값으로 바뀐다.
- 그림 자는 세 안이 같다. 바뀌는 것은 목표선·한도선 자리와 조각·막대뿐.
- 세 안 견주기 표·견주기 줄은 만들지 않는다 (U4, U4-1). 같은 자 위에서 길이가 차이를 말한다.
- 작은 회색 글씨를 데모 전체에서 없앤다 (7절).

## 1. 처음 고르기 (2단계 답 끝)
- 지금 `교육자료 찾기` 단추 자리에 질문 한 줄(15px 먹) "팀원 한 명이 하루에 얼마나 공부할 수 있나요?" + 단추 셋 `하루 1시간으로 찾기` · `하루 2시간으로 찾기` · `하루 3시간으로 찾기` (높이 44px, 한 줄, 390 에서는 세로로 쌓음). 곁글 없음, 권하는 표시 없음.
- 누른 단추의 말이 대화의 내 말이 된다: "하루 2시간으로 교육자료를 찾아 줘". 그 뒤 3단계는 지금처럼 진행 글과 함께 돈다.
- 4·5단계 단추(`12주 계획 짜기`, `리포트 보기`)는 그대로 하나씩. 고른 시간을 따라간다.

## 2. 바꾸기 (④⑤⑥ 쪽 머리)
- 부품: 진짜 라디오 `fieldset` (legend 는 화면 읽기용 "하루 공부 시간", 눈에는 안 보임). 세 칸 같은 너비, 칸당 높이 44px, 글 13px 500 "하루 1시간" 한 줄 (84시간 등은 그림 눈금이 말한다). 고른 칸은 바탕(먹 8%)·1px 먹 테두리·600 굵기로, 강조색 없음. 쪽 제목 오른쪽, 390 에서는 제목 아래 쪽 너비.
- 화면에 하나만: 3단계가 시작되면 ④·⑤·⑥ 쪽 머리에 같은 상태로 나온다 (쪽은 한 번에 하나만 보이므로 화면에는 하나).
- 바꾸면: 그린 단계(3·4·5 중 이미 한 것)의 끝 상태를 서버에서 한꺼번에 받아(또는 캐시) 같은 처리기에 `instant` 로 넣는다. ④ 조각·⑤ 막대·⑥ 공부 줄, 대화의 그 단계 답(큰 숫자, 한 줄, 표)이 제자리에서 바뀐다. 진행 목록은 다시 돌지 않는다.
- 움직임은 하나: 목표선(④)과 한도선(⑤)이 새 자리로 240ms transform. 조각·막대는 바로 끝 상태. 움직임 줄이기면 없음.
- 같은 값을 다시 고르면 아무 일 없음. 늦게 온 응답은 버린다 (abort + `budget_key` 비교). 실패하면 칸을 되돌리고 옛 그림을 둔다. 바꾸는 동안 `aria-busy`, 끝나면 알림 한 번 ("하루 3시간으로 바꿨어요"). 초점과 보던 쪽은 그대로.
- 3단계가 도는 중에는 고르기 칸을 `aria-disabled` 로 막는다.
- 새 공고를 넣으면 고른 값이 비워진다 (다음엔 다시 대화에서 고름).

## 3. 3단계 ④ 쪽과 답
- 막대 하나 (S1 유지). 막대 틀 전체 = 252시간. 목표선(2px 먹)은 고른 시간 자리, 틀 아래 눈금 84·168·252 (13px 먹, 숫자만 "84시간"). 막대는 공부할 거리 조각, 조각 길이 = 그 거리의 시간 합. 실습 자료 몫은 조각 안 빗금으로 (색만으로 가르지 않음).
- 막대 옆 "168시간 중 N시간" (지금 꼴, 고른 값으로).
- 답 맨 위: 큰 숫자 = 쓴 공부 시간 ("N시간"), 한 줄:
  - 하루 1시간: "84시간 중 · 큰 항목 17개를 자료로 공부해요"
  - 하루 2시간: "168시간 중 · 공부할 거리 28개 모두 자료로 공부해요"
  - 하루 3시간: "252시간 중 · 28개 모두에 따라 해 볼 자료까지 더해요"
  (개수는 저장본 값. 데이터가 다르면 데이터를 따른다.)
- 자료 역할 이름: 주 → "먼저 볼 자료", 보조 → "더 볼 자료", 실습 → "따라 해 볼 자료". 펼친 줄에서만.
- 진행 글 (S12): 세 안 모두 같은 틀 "공부할 거리 28개로 자료를 찾는 중" → "자료를 찾았어요", 그 뒤 안마다 실제로 일어나는 단계만 (0개인 단계 줄은 없음). 문구는 `budget-toss-writing.md` 표를 따른다.
- 가정 문장("길이를 모르면 3시간으로 어림" 등)은 화면에서 뺀다. README 와 저장본에만.

## 4. 4단계 ⑤ 쪽과 답
- 12주 세로 막대 하나. 세로 자는 세 안 중 가장 긴 주에 고정 (서버가 `peak_all` 을 보냄). 한도 점선은 고른 안 하나, 이름표 "한 주 N시간까지" (13px 먹).
- 큰 숫자 "프로젝트 일 300시간" 은 그대로. 한 줄만 고른 값으로: "한 주 N시간까지 · 12주 중 k주는 그 안에 해요". 넘는 주가 없으면 뒤쪽을 "12주 모두 그 안에 해요".
- 넘친 주 표시는 지금 규칙(빗금 + "+N시간"), 넘는 주가 있을 때만.

## 5. 5단계 ⑥ 리포트
- 줄마다 공부 칸만 고른 안의 자료로 바뀐다. 면접 질문·답·경험은 그대로. 머리에 따로 줄을 더하지 않는다 (쪽 머리 고르기 칸이 말한다). 복사한 글에만 "교육자료는 하루 N시간 기준" 한 줄.

## 6. 서버·상태 (frontend-ui-engineering 안)
- 새 endpoint 없이 `/api/run` 에 `budget` ("84"/"168"/"252"). 없으면 "84" → 지금 시험 그대로 통과. 이상한 값은 error 사건 하나.
- 안 목록은 서버가 보낸다 (`budgets: [{key, hours, per_day}]`). 화면이 84·168·252 를 지어내지 않는다.
- 사건마다 `budget_key`. 바꾸기용으로 기다림 없는 요청 (`speed: 0`).
- `store.js`: `budget`, `runs`(`step:budget` 캐시), `switching`. 주소 `?budget=` 는 `replaceState` 로 맞추고, 새로고침 땐 처음 고르기 단추의 초점 자리로만 쓴다 (저절로 돌리지 않음).

## 7. 작은 회색 글씨 없애기 (U4-1, 데모 전체)
- 12px 글과 `--muted` 색 글을 화면에서 없앤다. 각 줄은 셋 중 하나로: 지운다 / 꼭 필요하면 13px 이상 먹색으로 올린다 / 접힌 곳 안으로 넣는다. 기본은 지우기.
- 예외는 둘만: 단계 길의 아직 안 그린 쪽 이름(누를 수 없음을 알림), 입력창 안내 글(placeholder).
- 다시 틀기 알림("미리 돌려 둔 결과를 다시 보여 드려요 · 실제로는 N초")은 2절 규칙이라 남기되 먹색 13px 한 줄.
- 목록은 `design/proposals/budget-frontend-design.md` 의 회색 줄 목록을 따른다. 만드는 사람은 고친 줄마다 지움/올림/접음을 `design/reviews/v5-gray-log.md` 에 적는다.
- `tokens.css` 의 12px 크기 토큰은 쓰는 곳이 0이 되면 지운다.

## 8. shots.py 와 시험
- 새 사진: 처음 고르기 상태, 안마다 ④⑤⑥ 끝 상태 (세 너비), 84→252→84 바꾼 뒤.
- 검사:
  - 화면에 보이는 글 중 글자 크기 < 13px 이 0개, `--muted` 색이 7절 예외 밖에서 0개.
  - 안마다 답 머리 숫자 = 저장본, 그린 조각 수 = 자료로 공부하는 거리 수, 목표선 x = 고른 시간/252 × 틀 너비 (±1px), ⑤ 막대 높이가 세 안에서 같은 자.
  - 84→252→84 뒤 대화와 쪽의 글이 처음과 같음, 대화 메시지 수 그대로, 표가 쌓이지 않음.
  - 고르기 칸 높이 ≥ 44px, 화살표 키로 바뀌고 알림이 나옴.
  - 넘침·겹침 없음 (지금 검사 그대로).
- pytest: 안마다 parametrize 해서 숫자, 3·4단계 공부 합이 같은지, 리포트는 공부 칸만 다른지, budget 없으면 지금과 같은 사건.
- 끝낼 때 shots.py 한 번 전체 통과 (파일 고치는 동안 돌리지 않기), pytest 통과, README 갱신.

## 버린 것 (왜)
- 바꿀 때 지난 단계 다시 틀기 (frontend-design): 저절로 이어 돌리지 않는다는 규칙과 부딪히고, 같은 대화가 길어진다.
- 세 안 견주기 표·"하루 1시간보다 … 더" 줄 (ui-ux, taste, frontend-design): U4·U4-1. 같은 자가 차이를 보인다.
- 단추 곁글 "주 자료만/보조/실습" (frontend-design): U4-1. 차이는 고른 뒤 답 한 줄이 말한다.
- 기본으로 골라 둔 1시간 (ui-ux, taste): 단추 셋이면 기본값이 필요 없다.

## 9. 데이터가 온 뒤 정한 것 (리드)
데이터 결과: 84 → 17개·51시간, 168 → 28개·120시간, 252 → 28개·162시간 (`data_spec.md` 새 절, `budgets_hand.json`).
1. 목표에 못 닿는 시간(168 에서 48, 252 에서 90)은 지어내 채우지 않는다. ④ 막대에서 목표선까지 빈 칸으로 남고, 답 한 줄 끝이 "· N시간은 남아요"로 말한다. 까닭(빈 자리, 맞는 자료 없음)은 화면에 쓰지 않는다 (U4-1, 데이터에 있음).
2. 계획 시간은 자리마다 3시간 셈 그대로. 아는 길이는 화면에 내지 않는다.
3. 새로 찾은 주 자료 3개는 84 에 넣지 않는다 (84 = 발표에 나온 지금 안 그대로).
4. 84 화면의 자료 목록은 `budgets["84"]` 의 주 자료만. 보조("더 볼 자료")는 168 부터, 실습("따라 해 볼 자료")은 252 에서만 보인다. 모든 화면은 `budgets[key]` 하나에서 읽고 예전 최상위 열쇠는 읽지 않는다.
5. **(b1-lead 1번으로 바뀜. 옛 문구는 지웠다.)** 3단계 답 한 줄은 한 틀: "{목표}시간 중 · {N}개를 자료로 공부해요{더 얻는 것} · {남는}시간은 남아요". N 은 ④ 범례 "자료로 공부할 것" 수 (저장본에서 한 곳, `done.found`).
   - 84: "84시간 중 · 13개를 자료로 공부해요 · 33시간은 남아요"
   - 168: "168시간 중 · 26개를 자료로, 더 볼 자료까지 · 48시간은 남아요"
   - 252: "252시간 중 · 27개를 자료로, 따라 해 볼 자료까지 · 90시간은 남아요" (b1-lead 는 26 이라 썼지만 저장본·범례는 27)
   이름은 "공부할 거리" 하나. 한 줄이 한 줄에 안 들어가면(휴대폰 너비 포함) "· N시간은 남아요"를 뺀다 (`line_short`).
6. 한 주 한도 14·21·28 은 데이터 값. 세 안 모두 4·5주차가 넘는다 (프로젝트 몫 때문) — 지금 규칙대로 보인다.
