## 고침
1. **shots 경쟁 B 가 경쟁을 돌리지 않는다.** `shots.py:1419-1426` 은 경쟁 A 와 같은 페이지에서, ⑥ 에서 이미 `pick_budget(168)`·`(252)` 를 한 뒤라 168 의 세 단계가 모두 `store.runs` 에 있다. 그래서 168 바꾸기는 기다림 없이 끝나고 84 클릭은 그다음에 온다 (주석 "아직 받아 둔 것이 없는 안"과 다름). 고침: B 앞에 `await fresh_to_materials(p); await p.js(SLOW)` 를 두고 168→84 를 누른다 (C 와 같은 차림). 그러면 "늦게 온 168 이 84 를 덮지 않는다"를 실제로 본다.
2. **12주 계획을 멈춘 뒤 안을 바꾸면 ⑤ 가 옛 안으로 남는다 (재현함).** 84 로 ④ → `12주 계획 짜기` → 0.6초 뒤 멈춤 → 168 로 바꿈. 끝 상태: 라디오 168, ④ "168시간 중 120시간", ⑤ 는 그대로 "한 주 14시간까지 … 공부 51시간을 1~7주차에 나눴어요"(84 값). 한 화면에 두 안이 섞이는, 1라운드 반드시 1 과 같은 종류다. `main.js:663` 은 끝까지 그린 단계(`drawn`)만 다시 쓰고, 멈춘 ⑤ 는 `drawn`·`answers` 에 없어 손대지 않는다.
   - 고침: `switchBudget` 의 막기 검사(660) 바로 뒤, `ac` 를 만들기 전에 끝까지 못 그린 ⑤ ⑥ 쪽을 비운다: `if (!store.drawn.has('weeks')) { weeks.clear(); resetWeeks(); } else if (!store.drawn.has('report')) { report.clear(); resetReport(); }` (`reset` 을 부르면 `stopSwitch` 가 새 바꾸기를 끄므로 여기서는 직접). 대화의 멈춤 안내와 "다시 짜기" 단추는 두고, 다시 누르면 `store.budget`(새 안)으로 돈다 (609). shots 에 이 경우 한 줄: 바꾼 뒤 `#weeks-doc .cap-line` 이 없거나 새 안의 값.

3. **버려진 바꾸기를 알리지 않는다.** 재현 A 에서 168 을 눌렀는데 끝은 말없이 84 다 (라디오가 되돌아갈 뿐, 알림 칸은 12주 계획 진행 글로 덮임). 섞이는 것보다는 낫지만, 사람은 168 계획을 받았다고 여길 수 있다. 고침: `stopSwitch`(645) 에서 되돌릴 때 `announce(\`${perDayText()}을 그대로 써요\`)` 한 번. 또는 `runStep` 이 바꾸던 값을 새 `store.budget` 으로 넘기는 쪽 (spec 이 "버림"을 정했으니 앞쪽이 작다).
