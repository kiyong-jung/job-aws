# 정리 리포트 설계서 (리드가 다섯 설계안을 합침, 2026-11-18)

근거: `design/report_brief.md` 와 다섯 렌즈의 설계안 (frontend-design, taste-skill, ui-ux-pro-max, toss-writing, frontend-ui-engineering). 하위 에이전트의 파일 쓰기가 막혀 설계안 원문은 파일로 남지 않았고, 리드가 이 파일에 필요한 내용을 모두 옮겼다. `DESIGN_RULES.md` 1절(U4-1 포함)이 이 파일보다 위다. 함께 바뀌는 것: `exam_brief.md` (학기 16주, 7~8 중간고사, 15~16 기말고사).

## 0. 한 줄
리포트 줄의 얼굴은 요약이 아니라 **1단계의 그 형광펜 줄**이다. 같은 노랑, 같은 번호 배지(형광펜 안 맨 앞), 같은 글(공고 원문 한 글자도 안 바꿈), 같은 14px/1.7, 같은 절 이름. 다섯 안이 모두 같은 처방을 냈다.

## 1. 부품 하나 (fe-eng)
- `panel.js` 에서 `sentenceMark(n, text, {button, painted, echo})` 를 내보내 1단계 `flush()` 와 리포트가 같이 쓴다. 리포트 것은 `mark.hl.echo`: role·tabindex 없음.
- `link.js` 의 대상 선택자를 `mark.hl:not(.echo)` (또는 `[role=button]`)로 좁힌다. 안 그러면 리포트 인용을 원문 형광펜으로 읽는다.
- CSS 는 빼기만: `.hl { cursor:pointer }` → `.hl[role=button]`, 리포트 전용 배지 칸 규칙과 줄 바탕 `--hl-soft` 칠 규칙을 지운다. 켜짐은 echo 에 `data-lit`/`data-active` 를 달아 기존 `.hl` 규칙을 받는다. 노랑 hex 는 `tokens.css` 밖에 없다 (정적 시험).

## 2. 쪽 차례
1. 머리 한 줄: "핵심 문장 19개 · 실제 면접 질문 12개", 오른쪽에 `리포트 복사`·`글 파일로 받기` (목록 위로 올림. 390 에서는 머리 아래 한 줄).
2. 절 소제목: 1단계 원문과 같은 이름·모양(`doc-sec h4`): 부서소개 · 담당업무 · 자격요건 · 우대사항 · 팀메시지. 서버가 `row.section` 을 보낸다 (저장본 값, 화면이 짓지 않음). 형광펜 줄이 없는 절은 쓰지 않는다.
3. 줄 19개, 줄 사이 1px `--line` (상자 없음).

## 3. 접힌 줄 (`details.report-row[name=report]`, 한 번에 한 줄만 펼침)
- `summary` = 3칸 격자: [echo 형광펜 1fr][실제 질문 표시 auto][꺾쇠 16px].
- 형광펜: 배지(최소 24px, 한·두 자리 같은 폭) + 원문. 패널 글 칸 ≥ 520px (`@container`) 에서는 **한 줄** clamp, < 520px 에서는 **두 줄** clamp, 끝 "…". 펼치면 같은 노드가 clamp 를 풀고 전체를 보인다 (원문을 다시 쓰지 않음).
- `실제 질문` 표시: 실제 질문인 줄에만 (12개), 13px 먹, 1px `--line-strong` 테두리. < 520px 에서는 둘째 격자 줄로 내려 원문 시작에 맞춘다.
- 요약(`summary` 글, "-기")은 화면에서 뺀다. 복사·받기 글의 줄 제목으로만.
- 상태 (1단계 세 단과 같음): 쉼 `--hl` / 올림·펼침 `--hl-strong` + 배지 먹 바탕 흰 글 / 다른 줄을 볼 때 나머지 `--hl-soft`. 줄 바탕 칠·600 굵기 없음. 강조색 없음.
- 초점 고리는 summary 전체에, `outline-offset: 2px` (노랑 위 주황 2.78:1 을 피함).
- 펼친 줄의 summary 는 `position: sticky; top: 0` + 바탕 `--surface` + 아래 1px 선 (긴 답을 읽어도 그 형광펜 줄이 위에 붙어 있음).
- 움직임: `line` 사건마다 그 줄 형광펜이 1단계처럼 왼쪽→오른쪽 칠해짐 (`--t-paint` 520ms, 한 번). 펼치기·접기는 움직이지 않음. 움직임 줄이기면 처음부터 칠한 채.

## 4. 펼친 줄 (이름표 위·내용 아래, 이름표 13px 500 먹, 내용 14px 400 먹, 최대 38em)
| 차례 | 이름표 | 내용 |
|---|---|---|
| 1 | 역량 | 한 줄에 하나, 끝에 " · 필수" / " · 우대" (구분없음은 안 붙임) |
| 2 | 이 프로젝트에서 해 본 일 | 점 둘까지: "{주} : {프로젝트 일}" 하나, "공부 · {N}주차까지: {짧은 자료 이름} {종류}" 하나 (자료 이름은 링크, 없으면 "(자료는 아직 못 찾았어요)"). 공부 점만 공부 시간 안마다 바뀜. 교육자료 없는 줄은 공부 점 없음 |
| 3 | 실제 면접 질문 · {회사} / AI가 만든 질문 | 질문 15px 500 (쪽에서 가장 큰 글, 몸통에서 하나뿐) |
| 4 | 이렇게 답할 수 있어요 · 밑줄은 예시 숫자예요 | 점 3~5개, 점 하나에 한 문장. 예시 숫자는 먹색 점선 밑줄(1px, 2px 아래). 계획 숫자에는 밑줄 없음 |
| 5 | 덜 다루는 것 | 13·18번만, `why_ko` 그대로 |
| — | (단추) `공고에서 보기` | 36px, 좁으면 44px |
- "공고 문장" 칸은 지운다 (접힌 줄이 원문). `title` 속성은 쓰지 않는다 (숫자 뜻은 받은 글 파일에만).
- 주는 학기 주차, 서버가 만든 글: 시험 주를 걸치면 "6주차, 9~11주차" 꼴로 (시험 주를 일하는 주처럼 쓰지 않음). 화면은 계산하지 않음.

## 5. 리포트 줄 ↔ 공고 줄 오가기 (누르는 길)
- `공고에서 보기` → `store.back = {lid}` → ① 쪽으로 넘어감 (되돌아가는 방향 280ms) → 형광펜 n 고름(`data-active`), 원문 칸 안으로 스크롤, 초점은 그 형광펜. 알림 "공고의 3번 문장이에요".
- ① 쪽 상태 줄에 `리포트로 돌아가기` (store.back 이 있을 때만) → ⑥, 그 줄 펼침, 화면 안, 초점 summary. 단계 길 "6 리포트" 도 같은 복귀.
- 리포트가 그려진 뒤 ① 에서 형광펜을 고르면 상태 줄에 `리포트에서 보기` → 같은 결과.
- 새 공고·다시 만들기면 store.back 을 비운다. 공부 시간을 바꾸면 펼친 줄·초점·스크롤을 그대로 둔다.
- 지금의 올리기 짝은 남겨도 되지만 검사는 위 누르는 길로 한다 (① 이 ⑥ 아래 깔려 안 보이는 짝은 검사하지 않음).

## 6. 5단계 대화 답
- 큰 숫자 "실제 면접 질문 12개" 그대로. 한 줄: "형광펜 친 공고 문장 19개마다 해 본 일·질문·답을 정리했어요" (+ 넘치면 뒤를 줄임).
- 대화에 줄 목록·형광펜은 두지 않는다.

## 7. 데이터 (`design/build_report.py` 손 글, 모델 호출 없음)
1. `ans` → `answer_points` 3~5개, 문장마다 70자 이하 (목표 50자). 차례: 상황 → 한 일 → 숫자 결과 → 배운 것. 쉬운 말 앞, 전문어는 괄호 ("그림 품질 점수(FID)"). 해요체. 사실·숫자는 바꾸지 않고 쪼개기·다듬기만. 복사 글은 이어 붙여 한 문단.
2. `exp` 에서 주차 글을 뺀다 (검사: "주차" 낱말 없음). 주는 `week`(학기 주차로 옮긴 값)에서 서버가 만든다: 시험 주를 걸치면 "6주차, 9~11주차".
3. `example_numbers[].value` 가 답 글의 글자 그대로 들어 있게 (지금 62개 중 13개가 아님: 화살표·빗금 값은 둘로 나누거나 답 글을 값과 같게). 검사: 모두 `value in 답`.
4. 교육자료 짧은 이름 `short_title`(30자 이하)과 회사 짧은 이름 `company_short` 를 손으로. 검사 포함.
5. `line` 사건에 `section` 을 더한다.
- 토스 안의 고쳐 쓴 예 (7·10·13·14번)를 기준으로 19줄 모두 같은 규칙으로 쓴다. 예 (7번 답):
  - 학습할 때는 그림에 잡음을 단계마다 섞고, 모델이 그 잡음을 맞히게 해요.
  - 만들 때는 잡음에서 시작해, 예측한 잡음을 조금씩 빼며 그림으로 되돌려요.
  - 글은 임베딩으로 넣고, 가이던스로 글을 따르는 세기를 정해요.
  - Stable Diffusion은 압축한 공간에서 해서 빠르고, Flux는 잡음에서 그림까지 곧은 길을 배워요.
  - 제 64×64 모델은 걸음을 50에서 20으로 줄이자 그림 품질 점수(FID)가 41에서 45로 나빠졌어요.

## 8. 좁은 화면

## 9. 시험과 사진 검사
- pytest: `row.section` = 그 문장의 구역; `sentence`·`n`·`section` 은 세 공부 시간 안에서 같음; `answer_points` 3~5개·70자 이하; `value in 답` 모두; `exp` 에 "주차" 없음; 주 글이 7·8·15·16주차를 일하는 주로 쓰지 않음; 노랑 hex 가 tokens.css 밖에 없음.
- shots.py (1440·1024·390, 세 공부 시간):
  - 줄 n 마다 echo 글(배지 뺌) == ① `mark.hl[data-n=n]` 글 == 저장본 문장. echo 의 계산된 바탕·배지 높이·글자 크기가 ① 과 같음. `#report-doc` 의 노랑 칠은 echo 에만.
  - 절 소제목 차례 = ① 의 차례, 줄 번호가 저장본 section 과 맞음.
  - 접힌 줄: ≥520 에서 높이 한 줄, <520 에서 두 줄 이하. 실제 질문 표시 12개. 펼친 줄 ≤ 1.
  - 펼친 줄: 이름표 차례, 질문만 15px 500, 답 점 3~5, 밑줄 수 = 그 줄 예시 숫자 수, "공고 문장" 칸 없음, `title` 0.
  - 붙는 머리: 펼치고 300px 내려도 그 summary 가 보이는 칸 맨 위.
  - 가고 오기: `공고에서 보기` → 맨 위 쪽 posting, 형광펜 n `data-active`·보이는 칸 안·초점 → `리포트로 돌아가기` → report, 그 줄 open·초점. ① 에서 `리포트에서 보기` 도. 움직임 줄이기 포함.
  - 공부 시간 바꾸기: 펼친 줄·초점 그대로, 공부 점만 바뀜.
  - U4-1 전역 검사 그대로 (13px 아래·회색 0).
  - 지울 검사: 숨은 쪽 `data-lit` 만 보던 것, "줄 글 시작 x 같음".
